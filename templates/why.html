Why Make This? How We Got Here

Background

KrakenMeister's civ builder stopped working

KrakenMeister's civ builder is an awesome tool, but it was built against a snapshot of an older version of the game's data file. Every unit, tech, building, and string in AoE2:DE lives inside a binary file called empires2_x2_p1.dat. KrakenMeister's system baked in assumptions about that file - which ID slots were empty, which ranges of string IDs were safe to use - based on the game as it existed when it was written. DLC updates kept being released (thankfully), and those assumptions stopped being true.

The South American biome collision

The most visible breakage came from the Last Chieftans DLC. That update added new environmental units - herdable animals, huntable animals, predators, berry varieties, terrain objects - and the game engine assigned them fresh unit IDs in ranges that happened to overlap with the spare slots KrakenMeister used for custom unique units. The result: maps that were working fine before the DLC would suddenly spawn the wrong thing entirely. Instead of berries, herdables, huntables, and predators, you'd get patches of neutral (Gaia) unique units. Unfortunately this is the nature working within a set of previously free unit slots - each time DLC units are added, the civ builder needs to be patched (new 'free' slots found) in order to work properly.

The Idea

I used KrakenMeister's civ builder to build all of my custom civs. My brother and I would use these OP civs to beat up on as many extreme AIs as we could stand. Eventually, I started direct dat file editing - not via the AGE editor, but with Python. My thinking was that, this way, when the game DAT gets changed/patched I can simply run the script to regenerate my mod. When I wanted to create more elaborate and crazy civs, I employed AI: new unique units, aura effects, multiple technologies and bonuses, you name it.

Because my brother and I mainly played on Amazon Tunnel (a great map vs multiple AIs), I realized the problem after we would spawn with six Gaia unique units instead of berries, and four or five Gaia UUs instead of Capybaras. To fix this, I employed a script that would "patch" my civ mod. Now the pipeline for my mod was: create (or edit) civs in KrakenMeister's civ builder, combine all my civs with vanilla civs, generate the mod zip on KrakenMeister, download, apply my changes (new unique units, techs, etc), then apply a band-aid Last Chieftans DLC fix. This was getting complicated. After all of this editing, I was already part of the way to making a new civ builder.

What really galvanized my decision was a message in the KrakenMeister Discord. Some random user had posted how they had worked with Claude to create a working civ builder in a few hours: nothing fancy, just some dropdowns for bonuses and techs, but it seemed to work, according to their screenshots. I reached out to them via DM, and replied to their message, but, after days and days...nothing. There was only one thing left to do.

What Empire Forge does differently

Zero assumptions about the state of the game. Empire Forge reads your actual installed game files every time you build - it's not packaged with it. Rather than relying on a snapshot, it loads the real dat file from your machine, and uses only what is confirmed empty or safe in your current version of the game. Specifically:

  • Unit slots are verified by scanning all ~60 vanilla civs in the live dat before anything is written - if a slot isn't actually free, we don't use it.
  • String IDs are allocated from a pool extracted from your installed game's string file, checked at build time against what's actually occupied.
  • Civilizations All civs get read from your local game files; there will never be a civilization mismatch error.
  • Chronicles / Antiquity DLC civs (Achaemenids, Athenians, Spartans, Macedonians, Thracians, Puru) are detected and excluded automatically - they occupy civ slots in a separate pool that would corrupt if overwritten. Should any new Chronicles civs be added in future DLCs, those will be flagged and excluded as well.

Future-Proof

Lastly, and perhaps most importantly, you may have realized this isn't hosted on a web server. While this is a webpage, it's not hosted on the internet: all of this HTML and code is self-contained within the app. There are two reasons for this:

  • 1. No centralized data or website: No downtime, no outages, no dependency on me or my build tools - it's always accessible.
  • 2. I'm cheap. 🙂 But mostly number one.

In case of emergency, break glass

Besides a self-contained .exe, you can browse all of my code for free on Github: https://github.com/napkingcole/aoe2-empire-forge. In the future, should I stop updating this for any reason, *YOU* can download the code and spin up your own Empire Forge! The Github repository has everything you need: a few code dependencies are needed to get started, but after that you should be up and going. Don't know how to code? No problem! Contained in the repo is a folder, /llm, which contains a LLM Context Directory - the total sum of knowledge Claude Code has discovered over months of coding. If you were to utilize your coding agent of choice, that should be enough information about the nature of AOE2's dat file and genieutils to get you there.
